## The problem

When an import shipment gets flagged or delayed, a US trade compliance analyst has to reconcile manifest logs, restriction codes, and tariff clauses before drafting an official clearance response.
It is exacting, high-volume work where a wrong answer has legal weight.
An agent is only useful in that loop if the dangerous failure modes are structurally impossible, not just statistically unlikely.
That constraint - make wrongness unreachable, not improbable - shaped every design decision below.

This is a synthetic-data demo built as a portfolio piece: every vendor, manifest, and tariff clause is generated by seed scripts.
The architecture, though, is shaped exactly like the restricted system it imitates.

## Architecture

The system runs as a single FastAPI container on Cloud Run, scaling to zero between requests, with a React SPA talking to it over a server-sent-events stream.
Inside, a LangGraph state machine drives the agent loop against Gemini on Vertex AI, with retrieval over Pinecone and persistence in Firestore.

The part I care most about is what the model never gets to touch.
Vendor identity is resolved entirely outside the LLM: the `vendor_id` is pattern-validated at the API edge and bound server-side into the run's typed context.
Tools read their scope from that context - they are forbidden from even declaring a `vendor_id` parameter, so a prompt injection has no argument slot to land in.

```python
@tool
def lookup_shipment_manifest(
    shipment_id: str,
    runtime: ToolRuntime[VendorContext],
) -> ManifestRecord:
    """Fetch a manifest, scoped to the vendor bound at the edge."""
    vendor_id = runtime.context["vendor_id"]  # server-bound, never model-supplied
    ...
```

The agent has exactly four tools: classify the restriction, look up the manifest, retrieve tariff clauses, and draft the clearance response.
None of them can mutate shipment state.

One production war story: the SSE reasoning stream died in deployment because a CDN buffered it.
The fix was a split-origin setup - the SPA on Firebase Hosting, the API on a DNS-only subdomain straight to Cloud Run - which kept the stream unbuffered end to end.
The streamed reasoning is advisory display only; the draft that matters is always taken from the tool's own output, never reassembled from streaming deltas.

## Safeguards

Three rules do the heavy lifting.

First, a deterministic guard runs before the model.
Inquiries carrying sanctions flags, contraband indicators, seizure references, or bribery signals are matched by plain string and regex rules and routed straight to an escalation queue.
The LLM is not the first line of defense for international security rules, and a blocked run costs exactly zero model tokens.

Second, the agent drafts and stops.
Every draft is written with a `draft` status flag, and a human analyst takes a separate, explicit action to approve or reject it.
There is no code path from the agent to any external network - it physically cannot submit documentation anywhere.

Third, everything is audited.
Every tool call, classification, retrieval, and draft appends a trace document with the vendor, raw inputs and outputs, token counts, and latency, surfaced on a dedicated traces page in the UI.

## Impact

The demo is public with no sign-in, which makes spend control part of the architecture rather than an afterthought: a hard instance ceiling on Cloud Run, a provider-side token quota, and an in-app per-IP rate limiter that debits each run's actual token usage.
Idle cost is $0 by construction.
